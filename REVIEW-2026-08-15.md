## CRITICAL

1. **Generated update-rules hooks read `event.text`; the engine fires
   `event.reply`.** `src/features/studio/wizard/updateRules.ts:173` emits
   `on('reply_ready', (event) => { const said = (p) => String(event && event.text ? event.text : '').includes(p); ... })`.
   The engine (`agent/loop.py:1183`, `docs/hooks.md`) fires `reply_ready` with
   `{reply: "..."}` — `event.text` is always undefined, so every trigger-guarded
   `setvar`/`incvar` the wizard compiles is dead in production, silently. Your own
   test masks it: `updateRules.test.ts:86` feeds the fake sandbox `{text: "..."}`.
   Fix the emitted code to read `event.reply` AND fix the test fixture to the real
   contract shape (that is the lesson here: test fixtures must mirror the engine's
   fire() payloads, not the generator's assumptions).

## MAJOR

2. **The TS protocol gate un-refuses itself one event later.**
   `crates/transport/src/client.rs:409-414` emits `Frame{welcome}` then
   `status(Online)` back-to-back; `src/store/connection.ts:71-103` refuses the
   mismatched welcome (offline + localized reason) but the already-queued `online`
   status flips the store back to online and wipes `lastError`, before the async
   `disconnect()` lands. Net effect on a wrong-major engine: a flicker into a
   room-less play screen, then a silent bounce to the connect form with NO error —
   worse than the old Rust refusal. Fix on the store side: latch the mismatch
   (e.g. a `refusedProtocol` field that makes subsequent `online`/`offline`
   transport statuses no-ops until the next explicit connect attempt). Add a test
   that replays the REAL event sequence (welcome → online → offline), not a
   truncated one — the current test stops one event short.

3. **The round-trip CI job can never pass now.** `scripts/check_roundtrip.sh:44-45`
   hard-requires the engine's `ejs` extra (correct per the owner decision), but
   `.github/workflows/ci.yml` clones the engine without ever running
   `uv sync --extra ejs`. The roundtrip job (and the live-connect regression guard
   inside it) is permanently red in CI. Add the sync step to the workflow.

4. **`readRulepack` inverts the engine's `initiative:` contract.**
   `src/features/studio/split/rulepack.ts:186` flags `initiative` when it is NOT a
   string; the engine (`core/rulepacks.py:532-539`) REQUIRES a mapping with a
   non-empty string `roll` and rejects a bare string. The editor reddens the only
   valid form and greens the invalid one. Mirror the engine: require the mapping
   shape. Related minors: the starter sample (`PackWizard.tsx:344-353`) ends with
   `resolution:\n  kind: percentile`, a shape the engine rejects outright — fix the
   sample; and full-rulepack mode never populates `PackRulepackDraft.scripts`, so a
   rules script cannot ship from full mode.

5. **The ST/PNG export path drops the episode tag the release filter needs.**
   `loreToNative`/`pregenToNative` write `EPISODE_FIELD`, but `loreToStEntry`
   (`src/features/studio/exporters.ts:168-201`) emits no `episode` key — so every
   ST card and PNG the studio produces is untagged, and `filterEpisodeContent`
   passes it through whole: chapter-2 lore ships in the "up to episode 1" release.
   The serialized-module invariant ("the circulating file contains no
   future-episode content, by construction") must hold on ALL deliverable paths or
   the paths that cannot carry tags must refuse/warn at build when the project has
   episode-tagged content.

6. **The audio deck's shared `loop` default overrides the engine's per-layer
   default.** `src/features/play/AudioDeck.tsx:129` keeps ONE `useState(true)`
   loop flag across bgm/ambience/sfx and always appends `loop`/`once` to the
   command. A keeper playing an sfx one-shot gets an endless loop. Derive the
   default per layer (engine: sfx does not loop) — simplest: re-derive the
   checkbox default when the layer select changes, and omit the token when the
   user has not touched it.

7. **Player upload gating is dead in the UI.** `src/features/play/MediaDeck.tsx:102-108`:
   the Share button is never disabled, and the `uploadsEnabled` hint can never
   show for a real player because the engine unicasts `media_enabled` only to the
   keeper who toggled it — a joining player's store keeps `null` forever. Disable
   or hint on the reply-side rejection at minimum; if you want live gating for
   players, that needs an upstream ask (broadcast or welcome-carried flag) — add
   it to UPSTREAM_TODO rather than working around.

8. **Split/pack persisted stores write to localStorage with no quota guard.**
   `src/store/split.ts:139-157`, `src/store/pack.ts:1025-1069`: zustand persist
   calls `setItem` synchronously on every keystroke; a QuotaExceededError throws
   inside `set(...)` and breaks the edit. The repo's own precedent
   (`src/store/panels.ts`) wraps the same risk in try/catch — use a guarded
   storage wrapper for both stores (and consider `version:`+`migrate` while there;
   the pack schema grew this series).

# Second addendum — the five tail commits (verified same day)

Gates all green from an independent seat (771/771, cargo, roundtrip+live-connect),
e2cb160's six-store sweep + meta-test adversarially confirmed (a reintroduced raw
storage really fails the test by name), 77ca3e2/e7fa142 clean. **But three fixes
are needed before push:**

1. **e8b7c46's new sentence plants the exact bug class it fixes.** "Read the new
   value with `getvar(path)`" is FALSE in the engine, proven by live probes
   (probe source: kept by the reviewer, ask if wanted): the sandbox snapshot is
   built ONCE per turn (`agent/loop.py:263`); MVU writes land mid-turn (`:575`)
   and `variables_changed` fires at `:1199` — so for MVU-sourced writes (the
   import-card mainline, and the ONLY source of non-`set` ops) `getvar` returns
   the turn-START value or undefined. For the handler's own `setvar`, `getvar`
   returns the REQUESTED value, not the clamped stored one (probe: setvar 99 on
   a 0..10 var → getvar 99, store 10). The engine's own `core/hooks.py`
   docstring documents this staleness. Reword to: `getvar` sees the turn-start
   snapshot plus your own earlier `setvar`s (unclamped); mid-turn engine/MVU
   writes are not visible, and `delete`/`move` have no new-value semantics.
   While there: `prompts.ts:19` + `model.ts` DEFAULT_HOOKS list 4 events under
   a header saying "exactly" — the engine fires 6 (`clock_advanced`,
   `tool_use` missing). Complete the list or drop the word.

2. **05ec79a's payload table omits `tool_use` — the event where this rule
   matters most.** The engine fires `tool_use {tool, arguments}`
   (`agent/loop.py:974`, documented in `docs/plugins.md`); a hook reading the
   wrong field there makes a `denyTool` guard silently never fire — the exact
   silent-failure class the rule exists for. Worse, `packLint.test.ts` uses
   `tool_use` as its "unverified event stays quiet" specimen — factually wrong
   at engine HEAD and it will fight the fix; use a genuinely nonexistent event
   name there. Add the table entry + fix the test. Cheap hardening worth
   taking: strip comments and string literals before scanning (`// e.text is
the wrong key` currently flags), and skip member CALLS (`e.toString()`
   flags). Known-and-acceptable for an advisory rule, but note them in the
   rule's header comment: nested same-name callback params (`forEach(e => …)`)
   can misattribute; `async (e) =>`, destructuring and aliasing are unscanned.

3. **e2cb160 regression: the merge shim is gone but `version` stayed 1.** An
   old v1 blob written before the schema grew rehydrates AS-IS (same version →
   zustand skips the discard path), and `metadata.rulepackScriptSource.trim()`

   mismatch discard actually triggers (verified empirically: the discard path
   resolves clean, fresh defaults, no throw). Nit: the meta-test glob covers
   `{store,features}/**/*.ts` — add `.tsx` and consider `src/**` so a future
   persisted store elsewhere can't slip past.
