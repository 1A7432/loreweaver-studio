## CRITICAL

1. **The fields tab drops focus and loses the second keystroke under the real parent.**
   `PanelsEditor.tsx:401-404` re-parses `yamlText` on every prop change and
   `documentFromRaw` mints fresh `uid`s each parse; `commit` (`:409`) writes the
   serialized text up to `store.setPanelsYaml`, PackWizard hands it straight back as
   `yamlText`, the effect fires, every `PanelCard`/`BlockCard` gets a new React key and
   REMOUNTS — the focused input is destroyed. Probe (a `useState` parent, exactly
   `PackWizard.tsx:1359-1363`'s wiring): after typing one char into "Panel id" the
   element identity changed, `document.activeElement` was `BODY`, and the next key was
   lost (`tide-boardx` stayed `tide-boardx`). Same for "Title en". `PanelsEditor.test.tsx`
   masks it by passing `onChange = vi.fn()` — no feedback loop. Fix: remember the last
   text this editor itself emitted (a ref) and skip the re-parse when the incoming
   `yamlText` equals it; keep uids stable across the author's own edits. Add the
   stateful-parent test.

## MAJOR

2. **Slot vocabulary is wrong: the editor offers `sidebar|inline`; the engine accepts
   `sidebar|tray|modal`.** `panelsModel.ts:20`, `PanelsEditor.tsx` slot picker, i18n
   `studio.panels.slotName.*`, and the AI prompt (`panelsAi.ts:49` interpolates the same
   list, so the model is TAUGHT the invalid word). Engine: `core/panels.py:79`
   `PANEL_SLOTS = ("sidebar","tray","modal")`, `docs/authoring.md:401`. Ran the engine
   parser on a studio-shaped `slot: inline` file → `REJECT: slot must be one of
['sidebar','tray','modal']`. The `inline|sidebar` pair is `core/hooks.py` `UI_PANELS`
   — the hook `ui` FRAME's panel names, a different vocabulary. Worse on read:
   `panelsModel.ts:299` coerces any other slot to `sidebar`, so opening a hand-written
   `slot: tray` panel and touching anything silently rewrites it (verified: tray→sidebar,
   modal→sidebar). Your own repo already knows the right words —
   `scripts/gen_roundtrip_pack.ts:378,389` (`tray`, `modal`) and the play side
   (`PanelDeck.tsx:8`, `PanelMenu.tsx:18`). `panelsModel.test.ts:30` enshrines the wrong
   fixture (`slot: inline` in a file called "hand-written").

3. **zh-only text serializes as `{en: "", zh: …}`, which the engine refuses.**
   `panelsModel.ts:311-316` `writeLocalized` writes `{en, zh}` whenever zh is non-empty,
   including an empty `en`. Engine `_localized` (`core/panels.py:176-200`) rejects a
   present-but-empty locale: ran it → `REJECT: panels[tide-board].title.en: must be a
non-empty string`. So a Chinese-first author who fills only the zh box (which
   `problemsFor` accepts — it only needs ONE of en/zh) gets a file `--pack` refuses; and
   an engine-VALID hand-written `{zh: 水}` opens fine and is broken on the first edit.
   Fix: omit an empty locale (`{zh}` alone when en is blank; plain string when zh is
   blank; the pair only when both are set) — mirror `_localized`, which accepts any
   non-empty subset of `en`/`zh`.

4. **`choices` is an engine block kind the editor silently eats.** `core/hooks.py:95`
   `UI_BLOCK_KINDS` includes `choices` (`options[{id,label,input}]`, `prompt?` —
   `core/panels.py:352-378`); `BLOCK_FIELDS` (`panelsModel.ts:63-112`) has no row, so
   `readBlock` returns null → `dropped += 1` → gone on the next `commit`. The `dropped`
   count is computed (`parsePanelsYaml`) and never surfaced (`PanelsEditor.tsx:401-405`
   ignores `result.dropped`), so there is no warning either. Also lost on read: an OUTER
   `visible_when` on a `repeat` wrapper (`readBlock` `:233-238` reads only the inner
   block's condition; the engine accepts it on the wrapper — verified engine-OK, studio
   drops it). Either model `choices` (an `options` list field type) or at minimum keep
   unknown blocks as opaque raw entries and show the count — the commit's own
   standard ("an editor eating an author's work is the worst bug it can have").
   `panelsModel.test.ts:203-217` asserts the field table "mirrors core/panels.py" while
   pinning a list WITHOUT `choices` — a test that enshrines the drift.

## MINOR

5. Field mode menu offers `$leaf` on every field of every block (`PanelsEditor.tsx:77,93`);
   the engine only accepts `$leaf` inside a `repeat` template
   (`core/panels.py:157-158`, verified REJECT outside). Likewise `var`/`leaf` are offered
   for `path` fields (`src`) and `enum` fields (`style`), which the engine takes as plain
   strings only (verified `src: {$var}` REJECT). `problemsFor` should flag `$leaf` outside a
   repeat and a binding on a path/enum field, or the picker should hide those modes.
6. `writeScalar` turns a hand-written boolean `stat.value: true` into the string `"true"`
   (verified); engine accepts str for `stat`, so it builds, but the meaning changed.
   Read/write booleans as booleans.
7. `CharacterScreen.tsx:65-66`: pick a system without `make_char` in Describe mode, switch
   to Roll — `chosen` stays that id, the `<select>` shows the first option but the button
   is disabled with no hint. Reset `system` when the mode changes, or derive `chosen`
   from the mode's own list.
8. `CharacterScreen.tsx:191-192` sends `.st <name> <n>` from a `type=number` box; the
   engine reads a leading `-` as RELATIVE (`_apply_value_expr`: `-5` = current−5). A
   negative literal typed as an absolute value is applied as a decrement. Refuse a
   negative in the box until the engine has an absolute-negative form (see the upstream
   note below).
9. `en.json:200` `cardPathPlaceholder` suggests `cards/pilot.png` first — that is a RAW
   host path, keeper-only in the engine (`gateway/commands.py` `.import`: a non-pack ref
   is denied to players). Lead with the pack ref, and consider pointing at the
   `PackImportCard` picker (`.import list`, kind-aware since 614354b) instead of a typed
   path — the two entry points now duplicate each other, and only the picker knows `kind`.

## Addendum — all findings fixed 2026-08-18 (same day), verified

Every finding above is closed in the follow-up commit; each fix was re-checked the same
way the finding was made — by running `core.panels.parse_panels_text` over the studio's
REAL serializer output, and by the new stateful-parent editor test.

1. **Focus loss** — `PanelsEditor` remembers the text it last emitted (`lastEmitted` ref)
   and re-parses only text that is not its own; uids stay stable across the author's
   edits. Test `keeps the author's cursor` mounts the editor under a `useState` parent
   exactly as PackWizard does and types four characters into one field.
2. **Slots** — `PANEL_SLOTS = sidebar|tray|modal`, `satisfies` the protocol package's
   `PanelSlot`; slot names in both locales carry their meaning; the AI prompt gets a
   generated slot section typed `Record<PanelSlot, string>` (a slot the engine grows must
   be described to compile) and its test asserts `inline` is gone.
3. **zh-only text** — `writeLocalized` writes `{zh}` alone / plain `en` string / the pair,
   mirroring `_localized`; engine-verified accepted.
4. **`choices` + opaque carry-through** — BOTH. `choices` is modeled (`options` field
   type: id / sends / bilingual label rows, ≤ `MAX_UI_OPTIONS`=12, per-option
   completeness problem) AND any block the table does not hold is carried through
   verbatim as an opaque block, in place, shown as "kept exactly as written" with a
   count — never dropped; `problemsFor` skips it (the build is its judge); the AI gate
   REFUSES an opaque block from a model. `BLOCK_FIELDS` is now typed
   `Record<UiBlock["kind"], …>` over the protocol package, so a kind the engine grows or
   drops fails to COMPILE here. A repeat wrapper's own `visible_when` is modeled apart
   from the inner block's (`repeatVisibleWhen`); engine-verified both land.
5. `$leaf` offered only inside a repeat; `path`/`enum` fields get no source menu;
   `problemsFor` flags `leafOutsideRepeat` / `bindingNotAllowed`.
6. Booleans round-trip as booleans (engine-verified `value: true` stays `True`).
7. Character screen: the system box is derived from the CURRENT mode's list.
8. `sheetWrite(name, target)` writes the engine's explicit form `.st <name>=<value>`
   (engine 2.3): `=` assigns absolutely, so a negative target is written with its sign
   and a digit-bearing key cannot be mis-split — the two grammar gaps noted below are
   closed engine-side and this client no longer touches the bare form.
9. Card-path placeholder leads with the pack ref and points at the picker.
